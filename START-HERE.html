Add a project in a few minutes

  1. Open Project Studio and select Add project.
  2. Enter the title, short description, category, technologies, and repository or live demo links.
  3. Explain the problem and your approach. Add a concrete outcome in Highlight. Include metrics only when you can support them.
  4. Choose one of the included artwork styles or enter a cover image path. Use the arrows to reorder your projects.
  5. Choose Download data.js. Replace the existing data.js in this folder with the download. The filename must stay exactly data.js.
  6. Open index.html and check the new project. Then redeploy the folder on your host.

Save local draft keeps unfinished editing work in this browser. It is not a cloud backup. Download your content file to keep a portable copy.

Deploy on a static web host

This is a standard static website. It can be served by static hosting services, a Git-based website host, or a regular web server.

Host asks forUse
Project/framework presetStatic HTML / Other / No framework
Build commandNone — leave empty
Install commandNone — no dependencies
Publish/output directoryThe directory containing index.html (usually .)
Files to uploadContents of this extracted folder, including assets/

Upload-based host: upload the folder contents so index.html sits at the web root. Do not leave it one extra directory deep.

Git-based host: commit these files into your repository, select that repository in your host, and use the static settings above. For an existing deployment, push the changed files to its configured branch.

Existing web server: copy the files into its configured document root. No server-side runtime is needed.

For the ChatGPT-hosted version:

Attach your new data.js in the same conversation and say “Update my existing portfolio with these projects and publish it.” Editing Project Studio alone does not update the live site. The existing preview is private; uploading this ZIP to your own host uses that host’s sharing settings.

Use your own cover images

  1. Export a landscape image as WebP, JPEG, or PNG. Around 1200 × 800 pixels is a good starting point; aim below 200 KB.
  2. Put it in assets/, for example assets/my-next-project.webp.
  3. Enter that exact path in Project Studio’s cover field. You can also use an HTTPS image URL.
  4. Include the image when you upload the updated site. The data.js download does not contain image files.

The bundled cover art is an illustrative project concept, not a screenshot of the underlying application. Replace it with real project screenshots whenever you have them.

Future-proof editing habits

  • Keep project IDs unique and stable. Changing the title is fine; changing the ID resets saved-project associations.
  • Keep a backup of the ZIP and exported data.js before editing.
  • You can add more projects without modifying the layout code. New cards, counts, search results, and featured controls are generated from the project list.
  • To change personal information, edit the profile object in data.js. Also update the opening and quick-intro text in index.html where it mentions your name or education.
  • After editing, check a project dialog, the filters, résumé link, email link, and narrow mobile layout.
  • After redeploying, refresh without cache if an older version appears.

Change your portrait later

Your portrait is included as assets/sathwik.png and a pixel-preserving WebP copy at assets/sathwik.webp. Replace both with matching images, or update the picture/source paths in index.html. The same files are reused in the opening, your story and the quick intro.

Portrait tilt, following project labels and magnetic button effects run only with a mouse or other fine pointer. They reset when you scroll and respect both the motion control and system reduced-motion settings.

Compatibility & accessibility

Designed for modern Chrome, Edge, Firefox, and Safari, on desktop and mobile. Most layout and all content remain usable without motion. This is not a promise of support for every legacy browser.

The website works from a local file because it uses ordinary scripts and relative asset paths—no fetch calls or JavaScript modules. Local clipboard and storage features depend on browser permissions; copying email falls back to showing the address, and unavailable storage does not stop browsing.

Animations respect reduced-motion settings, can be paused, and stop offscreen. Scrolling is native. The brief entrance runs once per browser session, skips for reduced motion, and never blocks clicks. Keyboard interaction dismisses it immediately.

Source/content tests passed during development. Cross-browser visual and frame-rate testing was unavailable in the build environment; check your target devices before sharing publicly.
